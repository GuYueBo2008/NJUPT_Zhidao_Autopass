# polymas-auto（智慧树 / Polymas 智能体课程 自动看课）

基于纯 HTTP 请求实现的智慧树（Polymas）智能体课程自动看课工具：从**账号密码登录 → 选课 → 逐视频上报 → 复核**，全流程无需浏览器、无需手动点击。

**作者：** 古月波 ｜ **仓库：** [GuYueBo2008/NJUPT_Zhidao_Autopass](https://github.com/GuYueBo2008/NJUPT_Zhidao_Autopass)

> **本工具仅适配南京邮电大学（南邮）** 的统一身份认证（南邮 CAS）。其它学校的 CAS 认证方式**尚未验证、暂不清楚**，因此**不提供学校选择功能**，也不保证在其它学校可用。

## 功能特性

- 纯 HTTP 实现，**不需要 Selenium / Playwright 等浏览器**
- 账号密码登录，自动完成南邮 SSO → 智慧树 CAS → `ai-poly` 换取
- 自动列出课程、交互式选课（支持多选 / 全部）
- 分片增量上报（`--chunk`），观看时间线连续自洽，终端实时**彩色进度条**显示进度
- **多线程并发上报**（`--threads`，默认 8 / 最大 32）：每个视频一个线程同步推送，多个视频并行推进
- **可选真实节奏**（`--realtime`，也可在选课界面输入 `r` / `safe` 切换）：等到每片真的“看完”才上报，请求到达时间 ≈ 上报的观看时间
- **彩色终端界面 + 新手引导**：启动页展示作者、协议、**免责声明（按下任意键确认同意）**与使用说明，每步都有 `[1/4] ~ [4/4]` 步骤提示
- 确认声明后 **2 秒自动进入程序**；界面切换（首页→登录→选课→看课→返回选课）自动清屏，界面始终清爽
- 结束后自动**复核**完成情况
- 登录失败自动重试；全流程日志落盘，出错时汇总错误信息与堆栈，并给出下一步操作建议
- 密码输入以星号回显，并自动把输入法的全角字符转成半角英文
- 无颜色需求时可用 `--no-color` 关闭彩色输出

## 使用方法

### 交互模式（推荐）

```bash
python3 polymas_auto.py
```

流程：询问登录信息 → 列出课程并选择 → 开始看课（带进度条）→ 打印复核结果。看完**不会自动退出**，可继续选择其它课程，输入 `q` 才结束。

### 命令行参数

| 参数 | 说明 |
| --- | --- |
| （无参数） | 交互模式：登录 → 选课菜单 → 看课 |
| `--list` | 登录并列出课程后退出 |
| `--course <序号\|courseId\|名称片段>` | 只看指定课程 |
| `--all` | 看账号下所有课程 |
| `--select` | 强制进入交互选课 |
| `--term <term>` | 指定学期（默认用课程当前学期） |
| `--force` | 忽略已完成，全部重报 |
| `--dry-run` | 只查看，不上报 |
| `--chunk <秒>` | 上报分片步长，默认 60 秒；`0` 表示不分片（一次上报整段，最容易被识别，不建议） |
| `--threads <N>` | 并发线程数：**每个视频一个线程**，默认 8，**最大 32**（超出自动按 32 处理） |
| `--realtime` | **按真实时间间隔发送**：等到该片真的“看完”才上报，请求到达时间 ≈ 上报的观看时间（整批耗时 ≈ 视频总时长） |
| `--user <账号>` | 账号 / 学号（不填则启动时询问） |
| `--pass <密码>` | 密码（不填则启动时询问） |
| `--token <ai-poly>` | 已有 token 时直接使用，跳过 SSO 登录 |
| `--no-color` | 纯文本输出，不加颜色（适合旧终端或重定向到日志） |

也可用环境变量：`ZHS_USER` / `ZHS_PASS` / `AIPOLY_TOKEN`。

### 示例

```bash
python3 polymas_auto.py --list                 # 登录并查看课程
python3 polymas_auto.py --course 1             # 看第 1 门课
python3 polymas_auto.py --course 1 --force     # 忽略已完成，全部重报
python3 polymas_auto.py --all                  # 看账号下所有课程
python3 polymas_auto.py --course 1 --dry-run   # 只看，不上报
python3 polymas_auto.py --no-color             # 纯文本输出
```

## 工作原理

1. **登录链路**
   `南邮 CAS (i.njupt.edu.cn)` → `njuptsso.zhihuishu.com` → `login.zhihuishu.com (wxTransit)` → `passport.zhihuishu.com` → `cloudapi.polymas.com/oauth/login/ssoLogin`，最终获得 `ai-poly` 凭据（Cookie）。
   南邮登录参数使用 AES-CBC 加密，密钥由前端固定值派生。

2. **课程与资源**
   通过课程列表接口获取课程与学期，再通过资源树接口 `student-course/student/resource/queryTree` 遍历视频节点。

3. **上报（分片观看）**
   不会一次性把进度拉满，而是按 `--chunk`（默认 60 秒）把视频切成若干分片，逐片调用 `student-course/study/student/record/report` 上报：

   - `startWatchTime` / `endWatchTime` 逐片递增，呈现渐进式进度而非“瞬移”；
   - `studyTotalTime` 为该视频累计已看秒数，等于当前 `endWatchTime`；
   - `startDate` / `endDate` 与本次增量严格对应（**时间戳差值 == 本片观看时长**），相邻分片首尾相接，多个视频串成一条连续时间线，最后一片的结束时间贴近真实当前时间；
   - 分片长度、片间等待、视频间等待均带**随机抖动**，避免固定节奏这一机器特征；

   **并发说明**：`--threads`（默认 8，最大 32）会为每个视频开一个线程并行推送，各视频的请求几乎同时发出。
   为避免时间线互相矛盾，**时间线仍按顺序排布**（并发只改变“请求什么时候发”，不改变上报的起止时间），
   因此每条上报在时间上依然自洽、视频之间不重叠。代价是：整批上报会在很短时间内完成，
   若服务端把“请求到达时间”与“上报的观看时间”做比对，仍能看出时间线被压缩——
   要消除这层矛盾，请用下面的**真实节奏模式**。

   单个视频内部的多个分片始终**串行**推进（同一线程内按顺序发送），并发只发生在视频与视频之间。

   **真实节奏模式**：加 `--realtime`（或在选课界面输入 `r` / `safe`）后，程序不再压缩时间——
   每一片都等到真的“看完”才发出，实测相邻分片的实际发送间隔与上报增量**误差 0.000s**，
   到达时刻与上报的结束时间落在同一秒内。代价是整批耗时 ≈ 视频总时长：

   - `--threads 1`：一部接一部真实播放，总耗时 = 所有视频时长之和（时间线仍互不重叠）；
   - `--threads N`：N 个视频**同时**真实播放，总耗时 ≈ 单个视频时长（此时多个视频的观看时段会重叠）。

4. **复核**
   上报完成后重新拉取资源树，统计 `completeRate=100` 的视频数量并输出。

## 日志与排错

- 运行日志默认写入**程序同目录**的 `polymas_auto.log`（含时间戳、每步操作与错误堆栈）。
- 出错时控制台会即时提示 `[错误] 上下文：原因`，结束时打印**错误汇总**及日志路径。
- 退出码：有错误为 `1`，无错误为 `0`。

常见问题：

| 现象 | 处理 |
| --- | --- |
| 提示“用户名或密码错误” | 核对密码，注意结尾标点；密码框支持全角自动转半角 |
| 登录偶发失败 | 程序内置自动重试；仍失败请查看日志定位 |
| 中文显示乱码 | 程序已切换 UTF-8 代码页，如异常请使用新版终端 |
| 课程未完成 | 加 `--force` 重报，或查看日志中的上报错误 |
